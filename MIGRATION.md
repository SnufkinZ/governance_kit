# MIGRATION — installing or upgrading the governance kit

The fast path is the installer:

```bash
python governance-kit/scripts/install.py <new-repo-root>          # core install
python governance-kit/scripts/install.py <new-repo-root> --with-ci # + Docs workflow
```

It copies every file below to its target path, never overwrites anything that
exists, creates `tests/docs/__init__.py` and a stub `docs/SPEC.md`, and stamps
today's date into the priority board. This document is the same install
spelled out — read it to know what landed where and what you must edit.
**Re-running the installer is not an upgrade.** For an existing installation,
follow §6; existing scripts, rules, and tests are deliberately preserved.

## 1. Target layout

```
<new-repo>/
|-- CLAUDE.md                          # from templates/CLAUDE.root.md — EDIT the placeholders
|-- AGENTS.md                          # from templates/AGENTS.root.md — pointer to CLAUDE.md for non-Claude agents
|-- BOOTSTRAP.md                       # from kit root (deleted at maturity)
|-- .claude/skills/doc-audit/SKILL.md  # from templates/doc-audit-SKILL.md (Tier 4 runbook)
|-- scripts/
|   |-- check_docs_sync.py             # from kit/scripts/ — EDIT the two PORT constants
|   `-- check_bootstrap_phase.py       # from kit/scripts/
|-- tests/
|   `-- docs/
|       |-- __init__.py                # generated by the installer (empty)
|       |-- README.md                  # from kit/tests_docs/
|       |-- test_doc_consistency.py    # Tier 1 starter — extend as conventions grow
|       |-- test_doc_contradictions.py # Tier 2 starter
|       `-- test_ownership_gate.py     # Tier 3 unit tests (PORT fixtures if you edit scopes)
`-- docs/
    |-- CLAUDE.md                      # placeholder map of docs/
    |-- PRINCIPLES.md                  # from kit — EDIT/replace section 2
    |-- SPEC.md                        # generated stub — EDIT
    |-- WORKFLOW.md                    # from kit
    |-- design_doc_sync.md             # from kit
    |-- changelog/CLAUDE.md            # placeholder map
    |-- decisions/CLAUDE.md            # placeholder map + ADR-template.md
    |-- in_process/CLAUDE.md           # placeholder map + priority.md
    |-- audit/CLAUDE.md                # placeholder map
    `-- skill/
        |-- CLAUDE.md                  # placeholder map
        |-- design_template.md         # from kit/templates/
        |-- in_process_plan_format.md  # from kit/templates/
        `-- document_maintenance.md    # from kit/templates/
```

With `--with-ci`, `templates/docs.example.yml` also installs as
`.github/workflows/docs.yml` (skipped if one exists). It is a **separate Docs
workflow**, not a dependency of runtime build/image/deploy workflows. Making
Docs a required PR check can still block merging and indirectly delay release.
Keep `tests/docs/` out of your runtime test job
(`pytest tests/ --ignore=tests/docs`). No dependency manifest is needed for the
shipped workflow: it installs pytest and pyyaml directly, without pip caching.

## 2. What must be edited after install (the installer reminds you)

| File | Edit |
|---|---|
| `CLAUDE.md` (root) | Replace every `<placeholder>`: project context, repo tree. The working rules and doc references are ready as shipped. |
| `docs/SPEC.md` | One paragraph: what this project is. |
| `docs/PRINCIPLES.md` | Replace §2 with your domain principle, or delete it and keep Decoupling only. |
| `scripts/check_docs_sync.py` | `CODE_SCOPES` = your code roots; `CODE_EXEMPT_PREFIXES` = generated/vendored trees *under* those roots. |
| `tests/docs/test_ownership_gate.py` | Only if you changed the constants above: mirror them in the fixtures marked `PORT`. |
| `tests/docs/test_doc_consistency.py` | Add your code roots to `REQUIRED_CLAUDE_DIRS` (marked `PORT`) so the coverage test requires a `CLAUDE.md` map in each. |
| `.github/workflows/docs.yml` | Only if installed: adapt the Python version, and the default branch name if it is not `main`. |

Everything else is copy-as-is and domain-neutral.

## 3. The doc tests are starters, not the ceiling

The kit ships working Tier 1–2 suites (`pytest tests/docs/` is green in a
fresh install; each check starts biting when its convention is first used —
first plan doc, first versioned design doc, first `> **Code:**` line). They
cover the invariants `design_doc_sync.md` §2–§4 names: CLAUDE.md trees, link
resolution, in_process heads + Track, board coverage, Status vs board, snapshot
freshness, Version vs changelog, and ownership claims that match real files.

Growing beyond that is a normal Phase 0 → 1 activity: every new mechanical
invariant becomes one more test in `tests/docs/` whose failure message names
the exact file and fix (`tests_docs/README.md` has the pattern). The L2↔L3
freshness pin test is deliberately *not* shipped — build it when L3 exists
(`BOOTSTRAP.md` R0.2, `design_doc_sync.md` §3.1).

## 4. Bring-up order (matches BOOTSTRAP.md §2)

1. Run the installer; make the §2 edits; commit.
2. Sanity check (§5). All three commands should run clean.
3. Write the first design doc **before** its code, from
   `docs/skill/design_template.md`; give it a `> **Code:**` line.
4. Wire the Docs workflow if you did not use `--with-ci` (gate stays
   `--warn-only` in Phase 0).
5. Build. `python scripts/check_bootstrap_phase.py` tells you what Phase 0
   still needs; when it passes, do the Phase 0 tightening (flip the gate to
   blocking) and edit `BOOTSTRAP.md`.

## 5. Sanity check after install

```
python scripts/check_docs_sync.py --warn-only     # gate runs; no violations in a fresh repo
python scripts/check_bootstrap_phase.py           # reports Phase 0 status (exit 1 = "not yet" — expected)
pytest tests/docs/                                # all green out of the box
```

The gate needs a git base to diff against (`origin/main`, `origin/master`,
`main`, or `master`) — commit the install first in a brand-new repo.

## 6. Upgrade an existing installation

Use a reviewable branch or checkpoint. Compare the new kit against your
installed files and merge the changes below; do not overwrite customized files
with starter templates. The installer only fills missing paths and never
removes obsolete files. Its `--force` flag only permits installation into the
kit's host repo; it does **not** enable overwriting.

1. **Merge the gate and its tests together.** Update
   `scripts/check_docs_sync.py`, `scripts/check_bootstrap_phase.py`, and the
   three current `tests/docs/test_*.py` files from the kit. Keep local code
   scopes, generated/vendor exclusions, required map directories, extra tests,
   and other project-specific checks. Add the reference exclusion consistently
   to the gate and the two document-test modules. Preserve any local alternate
   reference directory names. The new ownership tests use disposable Git
   repositories to check both ordinary and merge-commit histories.
2. **Retire the draft inbox deliberately.** Before removing
   `docs/in_process/change_log_draft.md`, read its remaining entries: reconcile
   final contract changes in the authorized doc pass, and preserve unresolved
   rationale/questions in their owning plan or ADR. Then remove that obsolete
   inbox and `tests/docs/test_change_log_draft.py`, remove its `HEAD_EXEMPT`
   entry, and clean its references from maps, rules, and workflow docs. Do not
   discard pending facts merely because the new kit no longer ships an inbox.
3. **Merge the documentation policy.** Apply the changed working rule to root
   `CLAUDE.md`; merge `docs/WORKFLOW.md`, `docs/design_doc_sync.md`, the authoring
   skills, and the installed doc-audit skill. Preserve the project's approved
   contracts and domain rules. The no-doc-change threshold means no addition,
   removal, or change to a documented contract, not merely no new concept.
   Existing plan documents need not be mechanically reformatted; use the
   intent/analysis split for new plans and substantive revisions.
4. **Preserve bootstrap progress.** If `BOOTSTRAP.md` is still active, merge
   its workflow wording while keeping the current phase and graduation
   evidence. Do not reinstall it in a project that has graduated and removed
   it. Likewise preserve the live priority board and its status history.
5. **Migrate CI jobs, not the whole runtime workflow.** Install or merge
   `templates/docs.example.yml` into `.github/workflows/docs.yml`. In the old
   `.github/workflows/ci.yml` (or its renamed equivalent), remove only the
   migrated documentation jobs/steps and dependencies on those jobs; preserve
   runtime tests, build, and deployment. Exclude `tests/docs/` from runtime
   pytest collection. Keep the gate blocking if the project already graduated
   to Phase 1: do not reintroduce the example's `--warn-only`. Review required
   PR check names because the jobs have changed. Adapt the Python/default-branch
   settings and confirm that the Docs jobs run on a real PR in the target repo.
6. **Add workboard only if needed.** Re-run with `--with-workboard` and apply
   the printed pointer lines to existing maps (§7). Preserve existing live
   cards and boards. Instantiate one task card and receipt to check links in
   their mailbox locations as well as in the template directory. In a mature
   repo, install just the module's mapped files manually if re-running the
   full installer would recreate retired bootstrap files.
7. **Validate the merged installation.** Run `pytest tests/docs/` and
   `python scripts/check_docs_sync.py --base <pre-upgrade-commit>`; inspect
   DOCS OWED before committing and repeat against the same base after the
   upgrade is committed. For projects still in bootstrap, run the phase
   checker too (exit 1 means graduation is not yet complete). Review the final
   diff for preserved local settings, retired inbox references, and duplicate
   CI jobs. A passing local suite verifies the files; the actual Docs workflow
   run verifies GitHub event/base handling and runner setup.

## 7. Optional module — parallel workboard

Install with `--with-workboard` only if several agents, windows, or vendors will
work in the same repository at once. It adds:

```
docs/
|-- skill/parallel_workboard.md              # the protocol (levels L0–L3, Integrator, authority rules)
`-- in_process/
    |-- WORKBOARD.md                         # global runtime board — starts idle
    `-- workboard/
        |-- CLAUDE.md                        # map of the runtime directory
        |-- tasks/CLAUDE.md                  # card mailbox
        |-- receipts/CLAUDE.md               # completion mailbox
        |-- notices/CLAUDE.md                # coordination-event mailbox
        `-- templates/                       # task_card.md, task_receipt.md, coordination_notice.md
```

When the core maps are installed in the same run, the installer also adds the
module's pointer lines to `docs/skill/CLAUDE.md` (its tree must list every file,
Tier 1) and `docs/in_process/CLAUDE.md`. If those maps already existed, it
prints the lines for you to add by hand instead of editing your files. The
protocol carries no domain authority and is fully reversible: archive any
needed runtime records, then remove the board, the `workboard/` directory,
`docs/skill/parallel_workboard.md`, and the two pointer lines.
